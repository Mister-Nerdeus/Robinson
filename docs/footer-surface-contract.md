# Footer Surface Contract

## Purpose
The footer is a single compact contact surface that closes the page quietly.

## Must Include
- Public business identity.
- One dominant public phone CTA.
- Routine hours plus emergency policy context.
- Address and West Michigan service-area summary.
- Reachable `Privacy`, `Terms`, and `Accessibility` links.

## Must Not Include
- A second post-footer strip below the main footer.
- Duplicate primary/emergency phone rows when the number is identical.
- Boxed secondary route-link modules that compete with trust/contact content.

## Phone Hierarchy Rule
- If emergency and primary service lines resolve to the same number, render one dominant call CTA.
- Supporting context can still mention emergency call-first policy and routine scheduling hours.

## Homepage vs Task Pages
- Homepage and task pages use the same compact footer surface.
- No alternate boxed footer modules should render by route.
